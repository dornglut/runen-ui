## Row contract and completion rule

Every ID is permanent. New observations append the next zero-padded number in
their family; IDs are never recycled or changed because a proof moves. `DF-01`
through `DF-20` retain the accepted directional-corpus identities exactly.

Allowed statuses have these exact meanings:

- `blocked`: the owning implementation slice has not been accepted;
- `implementation-complete`: public behavior exists but its complete positive,
  negative, trace, validation, or downstream proof package has not passed;
- `proof-complete`: the complete exact-head proof package passes, but owner
  acceptance and merge remain pending;
- `owner-accepted`: public behavior, negative and trace proof, stable/MSRV
  validation, exact-head CI, owner review, and merge have passed.

`Required` in the M4 gate column means the row must be `owner-accepted` to close
M4. `M5 gate` identifies the accessibility behavior that deliberately does not
gate M4. Every M4C row requires slice-local causal trace before it may become
`proof-complete`; M4D1 normalizes and completes the schema but does not repair
missing causal parentage from an earlier slice.

A helper is valid proof only when it enters the canonical queue and preserves
normal target, owner, ordering, cancellation, trace, and reconciliation checks.
Counter and the downstream conformance package must use public framework APIs,
all transitional M1–M3 authorities must be removed by their assigned migration
rows, and `cargo validate` must pass at the exact reviewed head.
