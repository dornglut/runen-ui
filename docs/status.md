# Current Status

> **Category: Current status**

This file is the single durable owner of RunenUI capability maturity. It describes accepted default-branch capability, not active implementation progress, branch state, pull-request state, or blocker state.

## Maturity vocabulary

- **absent** — no accepted implementation exists;
- **planned** — roadmap/accepted target contract exists, but implementation is absent;
- **proof** — bounded implementation demonstrates the architecture/conformance contract but is not production breadth;
- **partial** — meaningful implementation exists but required production behavior is incomplete;
- **usable** — intended profile works for real downstream use with documented limitations;
- **stable** — compatibility/support policy is deliberately committed and release-grade;
- **deferred** — intentionally outside the active production path;
- **archived** — historical only; not active authority.

No current subsystem is `stable`.

## Milestone summary

M0–M5 establish the accepted headless foundation: typed authoring, persistent mounted/semantic identities, routed interaction, deterministic scheduling, trace/replay, and public testing.

M6–M7 establish renderer-neutral paint/hit publication, a reusable wgpu backend, winit input/accessibility adapters, and standalone/embedded host proofs. Their accepted scopes remain at `proof` maturity.

M8 completes its 33 production style/text/layout obligations; M9 completes its 25 visual composition and deterministic-motion obligations. The capability map distinguishes accepted features from remaining breadth.

M10 completes its 28 editing and interaction-service obligations, including application-owned documents, runtime sessions, clipboard/IME host services, logical scrolling, selection, and downstream/native integration.

M11 completes all 89 standard-control obligations. The library is `usable` for the accepted host-neutral profile, not a claim that M12 virtualization or M13 platform breadth is finished.

M13 has seven accepted framework input-arbitration obligations and three blocked native/Engine obligations; see the [M13 matrix](conformance/m13-conformance-matrix.md). Multi-window/multi-surface support, M12 virtualization, M14 tooling/performance and M15 release qualification remain outside the accepted scopes.

See the [roadmap](roadmap.md) for dependency sequencing and [conformance](conformance/README.md) for permanent behavioral and proof contracts.
