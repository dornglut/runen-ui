# Current Status

> **Category: Current status**

This file is the single durable owner of RunenUI capability maturity. It describes accepted default-branch capability, not active implementation progress, branch state, pull-request state, or blocker state.

## Maturity vocabulary

- **absent** — no accepted implementation exists;
- **planned** — roadmap/accepted target contract exists, but implementation is absent;
- **proof** — bounded implementation demonstrates the architecture/conformance contract but is not production breadth;
- **partial** — meaningful implementation exists but required production behavior is incomplete;
- **usable** — intended profile works for real downstream use with documented limitations;
- **stable** — compatibility/support policy is deliberately committed and release-grade;
- **deferred** — intentionally outside the active production path;
- **archived** — historical only; not active authority.

No current subsystem is `stable`.

## Milestone summary

M0–M5 form the accepted headless foundation: repository/tooling policy, typed core values, open widget/component architecture, mounted runtime/layout/style proofs, deterministic effects and routed interaction, trace/replay, semantic publication/action ingress, and public deterministic testing.

M6 is accepted complete at `proof` maturity: retained publication, canonical renderer-neutral paint/hit products, composition/resource/metadata/damage/capability semantics, independent-consumer proof, public testing convergence, and migration closure are accepted on the default branch. M7 is accepted complete at `proof` maturity: all twenty M7 conformance rows are owner-accepted, covering the reusable wgpu renderer/resource edge, reusable winit translation and AccessKit adapter edge, real offscreen/readback and golden evidence, standalone reference-host native input/presentation, the same Counter application exercised through deterministic headless and real native execution, and a separate winit-free downstream host-owned frame-loop proof over the accepted public runtime/publication/renderer/resource contracts.

M8 is accepted complete at its production-foundation scope: all thirty-three `M8STYLE-*`, `M8TEXT-*`, `M8LAYOUT-*`, and `M8INTEG-*` conformance rows are owner-accepted. M8A establishes production style resolution and invalidation; M8B establishes renderer-neutral international logical text and retained shaped-resource identity with renderer-owned SDF/MSDF realization; M8C establishes runtime-owned private-Taffy Block/Flex/Grid layout and exact final-layout text feedback; M8D closes the integrated production path by correlating Taffy available-space measurement, text reflow/artifact retention, measurement-to-paint shaped-resource identity, final semantic text/bounds, deterministic bundled-font public tests, retained retry/raster-scale re-realization, and real-wgpu multiscript evidence while removing replaced proof-era authorities.

M9 is accepted complete at its production visual/motion scope: all twenty-five `M9VIS-*`, `M9MOTION-*`, and `M9INTEG-*` conformance rows are owner-accepted. M9A establishes normalized RunenUI-owned geometry/brush/stroke/image/group vocabulary, common node decoration/static presentation, runtime ordering/composition/effect publication, conservative effect bounds, alpha-independent ordinary-shadow support and painter order, generic clips, explicit extension boundaries, private subordinate Lyon adoption, real-wgpu realization/reconstruction, and bounded renderer-private mask allocation/lifetime work. M9B establishes target-keyed transition policy in the existing style cascade, declarative owner-local explicit timelines, exact mounted-generation lifecycle, one runtime monotonic candidate instant, checked delay/repeat/zero-duration/forever timing, deterministic typed interpolation/discrete domains and fixed easing, explicit reduced-motion and mandatory-preference suppression policy, differential invalidation/cache/group lifetime, existing redraw/wake scheduling, atomic publication/retry correlation, and canonical motion diagnostics/trace. M9C closes the integrated production path by proving sampled presentation correlation across paint/hit/focus/semantics/presentation-relative clips including singular empty-hit behavior, ordinary public `ManualClock` timing/replacement/preference/layout/text/semantic integration, canonical hover/focus/active transition flow through existing interaction/style authority, representative real-wgpu motion over the accepted scene path with retained-publication retry plus cache and fresh renderer/device reconstruction, and final pre-1.0 cleanup to one truthful visual/composition/motion authority path.

M10 is accepted complete: all 28 conformance rows are owner-accepted on the default branch. M10B establishes exact application document/revision-scoped coordinates and one immutable caret, hit, selection, navigation, candidate-geometry, and transient preedit-projection map over the retained production text layout/artifact. M10C establishes application-owned document mutation/history, bounded owner-local runtime sessions and provisional chains, exact immediate update resolution and retirement/drain behavior, canonical routed editing defaults, editable semantic/AccessKit projection, and fail-closed sensitivity/redaction without a runtime document or alternate queue. M10D establishes one typed host-neutral service protocol, exact-session/token validation through the existing FIFO, fail-closed clipboard policy, committed-state IME/cursor requests, host-owned drag/drop custody, redacted diagnostics, deterministic fake-host proof, and selected real reference-host success/failure evidence. M10E establishes runtime-owned logical scrolling with correlated geometry, displayed-snapshot pointer selection, bounded touch gesture arbitration, and normalized controller commands. M10F closes the integrated path with downstream public-widget/testing/service proof, selected native reference-host and public controller normalization evidence, correlated real-wgpu editable rendering and retained-publication retry, and final single-authority cleanup. Broader platform and hardware coverage remains M13.

M11 is active at partial maturity on the accepted default branch. Accepted capability includes the Text/Button baseline with optional application-authored Button Unpressed/Pressed/Mixed semantics, application-controlled Checkbox/Switch and Radio controls, shared composite and collection focus navigation, typed standard-control semantic state with executable range/expansion actions, bounded focus-group type-ahead, scoped application-command transport/resolution converged across routed events and widget activation, scoped keyboard accelerators over that same application-command FIFO, standard ScrollContainer/ScrollBar affordances, application-controlled ListBox/OptionItem and TabList/Tab/TabPanel compositions, passive Separator/Image authoring, and same-surface presentation projection plus generic interaction lifecycle. The accepted presentation foundation retains one ordinary mounted/semantic lifetime, deterministic anchored placement and surface-band stacking, clipping and correlated geometry; it now also supports authored outside-pointer dismiss/block policies and modal input blocking, routed CancelOrBack dismissal without same-click retargeting, preserved exact pointer capture, focus Preserve/EnterAndRestore with existing FocusScope trapping, exact nested restoration/fallback, and bounded anchor-lifetime cleanup. Applications retain durable open/closed state. The accepted Menu family composes MenuButton/Menu/MenuBar/MenuItem/checkbox/radio semantics, app-owned submenu and checked state, generic focus groups and scoped commands, plus standard scroll and presentation dismissal without extra runtime authorities. Accepted standard Popover/Tooltip/Dialog compositions reuse these authorities: Popover provides authored placement/fallback and typed application-action dismissal; Tooltip remains nonfocusable/nonmodal with the exact owner `DescribedBy` relationship; TooltipTrigger uses mounted deterministic timers for hover/focus show/hide actions; Dialog composes authored modal semantics, existing FocusScope trapping and exact focus restoration. Accepted FocusVisible derives prominent focus indication through canonical focus, source modality and public text-input capability, including stable-owner promotion, inherited transfers, downstream recipe parity and typed trace; it does not change semantic focus. Accepted TextLayout provides one public downstream-achievable text-leaf measurement descriptor, logical inline/block alignment, Text Start/Start and Button Center/Center defaults, plus correlated retained paint, baselines, editing and hit geometry. Accepted SelectableText adds checked read-only application document/selection authoring without a mutation mapper, and reuses M10 routed selection, caret projection and typed Copy service while preserving existing M10 semantic action publication policy. Accepted Link adds true Link semantics, ordinary focus/pointer/keyboard and semantic application activation, disabled rejection and public custom-widget parity without framework URL/navigation ownership. Accepted single-line/multiline TextField composes application-owned source/selection and validation semantics with the one M10 edit/session/IME/clipboard authority, checked Unicode newline policy, M8 no-wrap/wrap measurement, routed optional Enter submit, and read-only/disabled authoring. Secret/password confidentiality, visual placeholder presentation, ComboBox and remaining standard-control, layout, and accessibility breadth remain M11 work; platform-aware access-key and environment integration remains M13 work.
